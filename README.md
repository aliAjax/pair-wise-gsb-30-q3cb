# 油品配送交接台

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

数据保存在浏览器 localStorage。系统把**配送单、罐车舱位、出库铅封、到站回单、结算行**串成同一张交接单，
解决"司机和油站各改各的、结算沿用旧回单"的问题。

## 业务规则落地

| 要求 | 实现 |
| --- | --- |
| 出库冻结油品、吨数、铅封号 | `freezeOutbound` 生成不可变冻结凭证（`FrozenManifest`），二次冻结直接拒绝；按舱位生成待结算行 |
| 到站异常让未结算部分失效、重算 | `recordArrival` 比对铅封/油品/吨数，异常时仅"待结算"行置为`已失效`（已结算历史不动）；必须 `supplementReason` 回原单补原因后才重算新行，不能另开新单 |
| 两个值班员确认同一回单只放行一次 | 同一值班员不可重复确认；满两名不同值班员自动产生唯一 `Released` 事件，放行后任何确认被拒 |
| 落盘失败从完整交接恢复，重试不多算油量 | 事件溯源 + 两阶段提交：暂存完整交接（命令+事件）→ 追加事件日志 → 写快照。管理台可注入"暂存后失败/提交中断"两种故障，恢复时先重放日志再重投暂存命令 |
| 重试不重复 | 每条命令带 `commandId`，`processedCommands` 全局幂等：重复确认、重复结算、重复恢复都不产生第二次效果 |
| 计价版本变化重核单价 | `changePrice` 版本号 +1，所有"待结算"行按新单价重算金额；已结算/已失效行不动，价格簿全程留版本历史 |

## 代码结构

```
src/domain/types.ts      领域模型、命令、事件
src/domain/reducer.ts    纯函数：命令校验(handle) + 事件应用(applyEvent) + 重放(replay)
src/services/storage.ts  事件日志 / 状态快照 / 暂存包（localStorage）
src/services/handover.ts commit 两阶段提交与 recover 崩溃恢复
src/stores/handover.ts   Pinia 接入：操作、故障注入、恢复、重置、审计日志
src/components/          建单表单、交接单卡片（冻结/到站/补因/确认/结算弹窗）、管控台、审计日志
```

关键不变量（均有自动化场景验证覆盖）：

1. 冻结后吨数以冻结值为唯一结算依据；
2. 失效行永不复活，重算只新增行；
3. 一张交接单全生命周期最多一条 `Released`；
4. 同一命令在事件日志与待结算行中最多生效一次——恢复/重试油量不翻倍。

## 演示路径

1. 列表里已有两张种子单（一张在途，冻结 18 吨）；
2. 新建配送单 → 出库冻结（填实装吨与铅封号）→ 到站登记；
3. 到站弹窗里点"铅封不符/油品不符/数量短少"可一键构造异常，观察待结算行失效 → 回原单补原因 → 重算；
4. 两名值班员确认放行 → 结算；
5. 管控台切换"暂存后失败/提交中断"再做一次操作，然后点"从完整交接恢复"，核对油量与结算行数不增加；
6. 调整计价版本，观察所有待结算行单价/金额重核，已结算行不变。
